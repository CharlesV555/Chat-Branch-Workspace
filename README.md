# Chat Branch Workspace

一个可离线加载的 Chrome / Microsoft Edge Extension（Manifest V3）。它在 `chatgpt.com` 注入分支式 Markdown 对话工作台，并通过原页面的输入框、发送按钮和回复区域与 ChatGPT 对接。

## 安装

### Chrome

1. 打开 `chrome://extensions/`。
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择整个 `chat-branch-workspace` 文件夹。

### Microsoft Edge

1. 打开 `edge://extensions/`。
2. 开启「开发人员模式」。
3. 点击「加载解压缩的扩展」。
4. 选择整个 `chat-branch-workspace` 文件夹。

加载或更新扩展后，刷新 `https://chatgpt.com/`。

## 当前工作方式

- 每次从工作台发送问题，当前 branch 下会立刻新增一个对话节点。
- 节点默认使用问题前 30 个字符命名；点击节点右侧铅笔按钮可手动重命名。
- 节点在等待回复时显示 `…`，同步完成后显示 `✓`。
- 扩展监听 ChatGPT 页面中新出现的 assistant 回复，在生成结束并稳定后保存到节点并显示在右侧。
- 点击节点会定位到右侧对应的一轮问答。
- 右侧只显示从根节点到当前选中节点这一条路径上的问答；同一棵树的其他支线不会混入。
- 发送新问题时，新节点默认接在当前选中节点后面；从较早节点继续提问即可形成另一条支线。
- 可把任意节点拖到同一 branch 的另一个节点上。被拖节点及其全部后代会作为完整子树迁移，已有问答内容不变。
- 为防止树结构损坏，不能把节点拖到自己或自己的后代下，也不能跨项目对话 branch 拖动。
- 每条用户消息和 ChatGPT 回复的内容左上角都有独立折叠按钮：`^` 表示当前展开，`v` 表示当前折叠。
- 折叠后仅保留内容首行预览；角色标识和问答标题保持可见。折叠状态会随消息一起保存在 localStorage。
- 点击右下角悬浮球可在 ChatGPT 原界面和分支工作台之间切换。

## URL 与本地数据

- 每条 ChatGPT 对话按 URL 路径使用独立的 localStorage 数据。
- 对于 `/g/g-p-.../project` 形式的项目页，整个 `/g/g-p-.../` URL 命名空间使用同一个项目存储作用域；单段或多段的细分对话 URL 都会记录到不同 branch 的 `remotePath` 中。
- 从项目页发送第一条消息时不会把 `/project` 当成最终对话地址；扩展会等待跳转后的 URL 稳定，再将实际细分对话 URL 绑定到当前 branch。
- 首个待回复节点会在触发原站发送键之前写入 localStorage；即使项目跳转造成整页重新加载，新页面也会恢复该节点并继续监听第一条回复。
- 在项目 graph 中点击已绑定的 branch，会直接切换到对应的 ChatGPT 细分对话页面；点击尚未绑定的新 branch，则回到项目页等待发起新对话。
- 如果通过 ChatGPT 原侧栏打开项目中的某条细分对话，工作台会按 URL 选中对应 branch；尚未记录的 URL 会显示为一个可重命名的占位 branch。
- 在 ChatGPT 首页发送第一条消息后，网址通常会从 `/` 变成 `/c/...`；扩展会把刚创建的工作台状态迁移到这个新地址，保持内容连续。
- 切换到另一个 ChatGPT 对话网址时，工作台会同步切换到对应的本地状态。
- 当前版本不会主动导入已存在对话的历史内容，只负责组织安装扩展后从零开始的对话。
- 数据只存储在当前浏览器，不会同步到后端。

## 本地对话库

- 每次创建对话节点或同步 ChatGPT 回复后，扩展都会自动更新一份跨 URL 的本地记录索引。
- 左侧「本地对话记录」会列出标题、节点数量和记录类型，不依赖 ChatGPT 原侧栏是否已经加载。
- 点击记录主体可直接查看 localStorage 中的完整本地副本；该模式为只读，不会与当前网页内容合并或处理冲突。
- 点击记录右侧的 `↗` 可打开记录对应的原网页；点击顶部「返回当前网页」可退出本地副本。

## 导入已有历史对话

1. 打开需要导入的 ChatGPT 对话，并等待当前可见消息加载完成。
2. 进入分支工作台，选择希望接收历史内容的 branch。
3. 点击右上角「检查历史对话」。再次点击可请求停止。
4. 扩展会定位原页面的对话滚动容器，分段向上滚动，并在每轮 DOM 更新后立即采集可见的 user/assistant 消息。
5. 连续三轮没有发现更早消息、达到顶部、运行 60 秒或完成 80 轮后停止；结束时恢复原滚动位置。
6. 采集结果优先按 `conversation-turn-*` 序号排序；没有序号时会合并每一屏 DOM 的相邻关系，而不是使用扫描发现时间。
7. 导入后默认重建为线性链：最久远的问答是根节点，之后每一轮依次成为上一轮的子节点，最新消息位于链末端。

导入会按页面 turn ID 和规范化后的用户消息内容去重，不会清空已有本地节点。基础 DOM 转换会保留标题、段落、粗体、斜体、链接、列表、引用、行内代码和 fenced code block。复杂表格、公式、图片及交互组件仍可能退化为纯文本。

## 已知边界

ChatGPT 的页面结构不是稳定接口。如果原站调整输入框、发送键或回复容器的结构，桥接可能需要更新选择器；工作台底部会显示同步状态或错误信息。

## 项目结构

```text
chat-branch-workspace/
├── manifest.json
├── content.js
├── style.css
├── README.md
└── vendor/
    └── markdown-it.min.js
```

项目不使用 React、npm、构建工具或后端。
