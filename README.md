# Chat Branch Workspace

一个可离线加载的 Chrome / Microsoft Edge 扩展（Manifest V3）。它保留 `chatgpt.com` 的原生消息、Markdown、代码块与输入框，在页面上增加本地 Git Graph、对话路径过滤，以及 Markdown 标题章节和代码块折叠。

扩展不使用 React、npm、构建工具或后端；数据只保存在当前浏览器的 `localStorage` 中。

## 安装

### Microsoft Edge

1. 打开 `edge://extensions/`。
2. 开启「开发人员模式」。
3. 点击「加载解压缩的扩展」。
4. 选择本仓库根目录，也就是包含 `manifest.json` 的 `Chat-Branch-Workspace` 文件夹。
5. 加载或更新扩展后，刷新 `https://chatgpt.com/`。

### Chrome

1. 打开 `chrome://extensions/`。
2. 开启「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本仓库根目录。
5. 刷新 `https://chatgpt.com/`。

新增或修改源码后不需要构建：在扩展管理页点击此扩展的「重新加载」，再刷新 ChatGPT 页面即可。

## 两种界面模式

### 原生增强模式（默认）

- ChatGPT 原生页面仍是消息和输入的唯一主要界面。
- 左侧浮动面板显示当前对话的本地 Git Graph。
- 面板可以收起为一个小按钮。
- 点击 graph 节点只负责滚动到该轮用户问题的开头并短暂高亮，不改变挂载点或当前专注。
- 「显示全部」可以立即恢复所有已加载的原生消息。
- 不复制或重新渲染 ChatGPT 的 Markdown，因此表格、引用、公式、图片、链接、代码工具栏等仍由 ChatGPT 自己处理。

### 实验工作台

右下角「实验工作台」按钮保留了旧版全屏工作台，便于继续实验自定义界面。进入实验工作台后，原生增强面板暂时隐藏；按钮会变为「原生增强」，用于返回原生页面。

旧工作台仍使用 `markdown-it` 和自定义输入框桥接。它不再是默认模式，也不是新功能的数据来源。

## 白天与夜间模式

- Git Graph 面板右上角的主题按钮按“跟随浏览器 → 白天 → 夜间”循环切换。
- 首次安装和没有保存偏好时默认为“跟随浏览器”，使用 Edge 提供的 `prefers-color-scheme` 设置。
- Edge 的系统颜色偏好变化时，“跟随浏览器”模式会立即响应，无需刷新页面。
- 主题偏好单独保存在全局 `localStorage` 中，对所有 ChatGPT 对话生效；它只改变扩展面板，不强制修改 ChatGPT 网站本身的主题。

## 对话图的含义

- 一个节点代表一轮用户问题和助手回答。
- 所有节点通过 `parentId` 形成树。
- 点击节点主体只定位原生消息，不改变父子关系。
- 节点右侧的 `◎/●` 圆形按钮设置挂载点；下一轮问答会成为该节点的子节点，创建后挂载点自动推进到新节点。
- 节点右侧的 `☆/★` 圆形按钮创建专注；一个专注表示从根节点到该节点的完整路径。
- 未激活的挂载与专注按钮仅在鼠标悬停节点或键盘焦点进入节点时显示；当前挂载点和已有专注始终可见。
- 再次点击已有专注的 `★` 会删除该专注；如果它正在生效，正文和 graph 自动恢复“显示全部”。
- 点击操作区中的专注，只显示该路径的原生问答；点击「显示全部」退出专注。
- 在专注状态下继续发送消息时，当前专注的目标会随新节点一起推进，保证正在发展的思路仍然可见。
- 双击节点名称或专注名称可以编辑，去除首尾空格后必须为 1–99 个字符。
- 点击原生发送按钮、按 Enter 或触发表单提交时，扩展会先创建等待节点；原生消息 DOM 出现后再自动绑定并补全回复状态。
- 节点可以拖到另一个节点上，操作会移动整个子树；扩展会阻止把节点移动到自己或自己的后代下。
- 拖动不改变节点与原生消息之间的定位身份，也不改变位于子树中的挂载点。
- 拖动后，所有指向被拖节点或其后代的专注都会删除；子树以外的专注不受影响。
- 点击的节点暂时不在 ChatGPT 当前 DOM 窗口时，扩展会根据节点顺序向前或向后滚动，等待虚拟化消息重新进入 DOM 后再定位和高亮；再次点击其他节点会取消前一次查找。

### 上下文边界

挂载关系、拖拽、专注和隐藏只改变本地组织与显示，不会修改 ChatGPT 后端保存的上下文。

例如原始对话为 `A → B → C → D`，把 B 设为挂载点并发送 E 后，对话图可以显示为：

```text
A → B → C → D
     └────→ E
```

但 E 仍通过当前 ChatGPT 对话的原生输入框发送，模型可能继续收到 C 和 D。当前版本不调用 ChatGPT 私有 API，也不会为了制造真实分叉自动创建新的对话 URL。

## 专注过滤

- 点击一个专注：正文和 graph 都只显示从根节点到专注目标节点的祖先链，无关节点暂时折叠。
- `显示全部`：退出当前专注，恢复当前页面已经加载的全部原生问答。
- 被过滤的问答只添加 CSS 隐藏类，不会被删除或重新生成。
- 如果某个历史节点尚未加载到页面 DOM，graph 仍可保留该节点，但必须先让 ChatGPT 加载对应历史，才能滚动定位或控制其显示。

## 加载历史消息

- 进入新对话页面时，扩展只识别当前已经存在于 DOM 中的消息，不会自动向上滚动抓取历史。
- 面板顶部的「加载历史消息」会根据原生轮次序号和 ChatGPT 自带的“加载更早”控件判断边界。
- 检测到首个已加载轮次不是第 0 轮，或存在原生加载控件时，按钮显示为绿色并可点击。
- 已到第 0 轮时按钮变灰并禁用；无法可靠判断边界时也保持灰色，不会擅自滚动。
- 点击后才会逐段向上滚动、等待 DOM 更新并收集更早轮次，最长运行 60 秒。
- 新发现的历史轮次会插入当前线性路径的根部，不改变挂载点和现有本地父子关系；结束后尽量恢复点击前的阅读位置。

## 原生 Markdown 折叠

扩展直接装饰 ChatGPT 已渲染的 assistant DOM，不再次解析或渲染 Markdown。

- Markdown `h1`–`h6` 标题旁会出现章节折叠按钮。
- 代码块前会出现独立折叠按钮和代码行数。
- 标题按钮悬停时显示当前章节的 DOM 派生行数。
- 折叠后显示注释输入框。
- 注释非空时按钮显示为绿色。
- 折叠状态和注释写入当前对话的 v4 `localStorage` 数据。

代码块行数来自代码文本，可以准确计算。ChatGPT 页面没有提供原始 Markdown 源码，因此标题章节的行数是根据渲染后 DOM 推算的，不保证等于原始 Markdown 文件行数。

## 本地数据

原生增强模式使用 `chatBranchWorkspace:v4:` 前缀，旧实验工作台继续使用 `chatBranchWorkspace:v2:`。两套数据不会互相覆盖。

v4 状态主要包含：

```text
nodes        图节点、父节点、原生 turn 标识和内容指纹
activeNodeId 当前定位选中的节点
attachmentNodeId 下一轮问答的挂载点
focuses      专注名称与目标节点
activeFocusId 当前用于过滤显示的专注
displayMode  focus 或 all
folds        原生标题章节和代码块的折叠、注释状态
```

旧 v3 状态首次读取时会复制迁移到 v4：有效的 `main/branch-*` 会转换为专注，空分支丢弃；迁移后不再使用旧 branch/ref 逻辑。

从 ChatGPT 首页发送第一条消息并跳转到 `/c/...` 时，扩展会把首页暂存的 v4 状态迁移到新的对话路径。切换到其他 ChatGPT URL 时会读取该路径自己的状态。

## 暂时独立的旧功能

旧版的本地对话库仍保留在实验工作台代码中，尚未接入原生增强模式。原生增强模式已有独立的按需历史加载流程，不复用旧工作台的消息渲染或输入框逻辑。

原生增强模式首次进入一条对话时，会把当前页面已经加载的问答建立为线性节点链；它不会主动滚动页面抓取未加载的更早消息。

## 项目结构

```text
Chat-Branch-Workspace/
├── manifest.json
├── content.js                 # 旧实验工作台与模式切换按钮
├── style.css                  # 旧实验工作台样式
├── native.css                 # 原生增强面板、过滤和折叠样式
├── src/
│   ├── storage.js             # v4 localStorage 与 v3 数据迁移
│   ├── chatgpt-adapter.js     # 原生 DOM 识别和问答配对
│   ├── focus-model.js         # 节点、挂载点、专注与子树移动模型
│   ├── focus-panel.js         # 操作区、专注列表和可拖拽对话树
│   ├── folding.js             # 原生标题章节与代码块折叠
│   └── native-app.js          # 原生增强模式协调器
├── tests/
│   ├── focus-model.test.js
│   └── storage-v4.test.js
└── vendor/
    └── markdown-it.min.js     # 仅供旧实验工作台使用
```

## 已知边界

ChatGPT 页面 DOM 不是稳定接口。当前适配器既支持 `conversation-turn-*`、`data-message-author-role`，也支持新版页面的“你说 / ChatGPT 说”语义标题、`data-user-message-bubble` 和消息 ID。存在多个 `main` 时会选择有真实可见尺寸的对话区域；定位时滚动到有实际布局尺寸的消息内容，而不是可能采用 `display: contents` 的外层容器。ChatGPT 调整这些结构后，可能仍需更新 `src/chatgpt-adapter.js`。

扩展只依赖原生渲染结果，不依赖 ChatGPT 私有 React 组件或私有网络 API。

有 Node.js 时可以运行：

```powershell
node tests/focus-model.test.js
node tests/storage-v4.test.js
node --check content.js
Get-ChildItem src/*.js | ForEach-Object { node --check $_.FullName }

# 可选：用 Edge 对保存的 ChatGPT 完整网页执行 DOM、graph 与滚动定位回归
node tests/fixture-browser.test.js "C:\path\to\chat-1.html" "C:\path\to\chat-2.html"
```

最终仍应在 Edge 扩展管理页重新加载，并在登录后的 ChatGPT 页面检查实际 DOM 兼容性。
